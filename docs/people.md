# Person profiles: the first ECCP pass

The unit of work is **one ECCP biography and its subject**, not a bulk import of every connected pedigree. The first subject is 曾紀澤. A basic profile is not a claim that its whole biography, every mention, or its genealogy has been checked.

## Authoritative record

Each person has a stable Ren-Wen ID and one JSON file in `data/people/`. The index lists filenames, not a duplicate list of biographical values. Source-specific passages and the existing mention IDs remain unchanged. A profile is independent of an article, its title, and of CBDB/Geni identities. The reader's original `catalog.json` person summaries remain preliminary seed summaries; the structured files are the authoritative detailed profile records as subjects are processed. Do not copy completed profiles back into those summaries as independently editable facts.

Read `profiles.html` from the webapp's **People · 人** link. The page derives the canonical name and age, displays the supporting sources, links to the two reader accounts, and exposes the JSON record for agents. Profile edits are reviewed repository changes; the existing browser proposal queue still edits mention identifications, not profile facts.

## Canonical name

The display convention is `[籍貫] 姓名（字或號）`, for example:

`[湖南湘鄉] 曾紀澤（劼剛）`

Store surname, given name, native place, zi, hao and romanizations separately. Select one sourced zi or hao for the parenthetical; retain all other attested names with their types and evidence. Prefer a known zi initially, otherwise a suitable sourced hao; never infer the type from the spelling alone. Display punctuation is a UI convention, not an assertion about source punctuation. Do not prepend offices, noble titles or posthumous honors to this canonical name.

Native place is **籍貫**, not automatically birthplace, residence, 郡望, or a modern administrative equivalent. Keep the attested historical place label. Missing native place or alias is null and is omitted from the rendered name, not invented. Empty typed-name lists mean not yet entered. Unknown surname may remain null; do not fabricate a surname or apply this Chinese naming pattern to foreign names without appropriate data.

The canonical string is generated by Python and JavaScript helpers from the same fields. It is not a second editable name field. Source wording, including ECCP's Wade–Giles forms, remains untouched.

## Chinese life years and sui

`life.birth.chineseYear` and `life.death.chineseYear` use the Gregorian-number label of the year **in which that Chinese civil year begins**. Thus the label describes a Chinese year, not January 1–December 31. Store the era, era year, original expression, precision, source and normalization basis alongside it. The first implementation accepts CE year labels; BCE and disputed calendar reconstructions require an extension, not a guess.

For resolved years in the same Chinese civil-year convention:

`age in sui = event Chinese year - birth Chinese year + 1`

This is an explicit project convention. It does not change on the person's birthday and is not Western age. A January/February event must be assigned to the appropriate Chinese year before calculation. The code does **not** convert dates or reuse the main reader's Western viewing-year slider as a Chinese year. When either Chinese year is unresolved, the result is null, even when Western dates are available. Estimates, alternatives and a source-reported age must not be silently converted into an exact birth/death year.

Western dates remain separate **source claims** in `life.westernDates`. A source's reported age remains in `life.reportedAges`; computed age is derived. Agreement is a consistency check, not independent corroboration. The first profile retains ECCP's March 12 death-day reading as unadjudicated, without changing the text or using it to override the source-supported death year.

## External identity mappings

Reserve both `externalIds.cbdb` and `externalIds.geni`, including when the value is null. Use `not-searched`, `unresolved`, `candidate`, or `matched` to distinguish discovery from identity resolution. Record the URL, matching evidence, method, source and date of checking. **IDs are decimal strings**: Geni's identifiers are too large for JavaScript's safe integer representation. Never derive them by parsing a number or translating a name.

The first mappings are CBDB `34348` and Geni `6000000012827521360`. They were checked against public indexed records, not a successful full API response. This limitation remains in the records. No bulk CBDB extract or Geni pedigree is bundled or relicensed. Sources retain their attribution and applicable terms; these files do not alter either external service.

Use Geni for genealogical discovery and preserve its profile link, but record the evidence and review status of each imported relationship independently. A matched person ID does not verify every relative or authorize overwriting local evidence with a remote merge.

## One-biography workflow

1. Create or reuse the subject's local person ID; do not duplicate it under another spelling.
2. Extract the native-place, name and date claims, preserving uncertainty and the original forms.
3. Match CBDB/Geni IDs with contextual evidence; leave unresolved slots visible.
4. Link ECCP and the relevant 清史稿 account; annotate occurrences without changing source wording.
5. Review names, dates, events and genealogy independently; record which parts remain unchecked.

The current record is `agent-proposed`, not attributed to a human reviewer. Other pilot people remain unprocessed. The complete ECCP entry and a full genealogy audit are subsequent work, not implied by this profile.

## Validation and derived SQL

```sh
python scripts/profiles.py validate
python scripts/profiles.py list
python -m unittest discover -s tests -v
npm test
python scripts/renwen.py build-db
python scripts/profiles.py index-db
```

The last command indexes profiles into the **same** derived `build/renwen.sqlite`: `person_profiles`, `person_names`, `person_external_ids`, and `person_profile_summary` (a view with derived sui). It checks that each profile joins a person entity already in the corpus. Always rerun it after rebuilding the corpus DB. CI does both steps before uploading the SQLite artifact. This database is not independently editable.

Tests cover typed name selection, missing fields, source requirements, exact string IDs, January/Chinese-year distinction, no fallback from Western dates, and idempotent SQL indexing. The new format is a profile data model, not a replacement for ctext's textual annotation XML.
